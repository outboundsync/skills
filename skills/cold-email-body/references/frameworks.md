# Cold email body frameworks

Use **one** framework per email. Default is Signal → Problem+Solution → Proof → soft CTA.

## 1. Default: Signal → Problem+Solution → Proof → soft CTA

| Beat | Job | Length |
| --- | --- | --- |
| Signal | Prove relevance with a verifiable observation | 1 sentence |
| Problem + Solution | Name the pain and the mechanism (not features) | 1–2 sentences |
| Proof | One tight peer/result proof | ≤1 sentence |
| Soft CTA | Single interest ask | standalone line |

Skeleton:

```text
{{signal}}.
{{problem + mechanism}}.
{{one proof}}.
{{soft CTA}}
```

## 2. PAS (Problem → Agitate → Solve)

| Beat | Job |
| --- | --- |
| Problem | Concrete pain for this ICP |
| Agitate | Cost of status quo (time, waste, risk) — no drama theater |
| Solve | Mechanism + soft CTA |

Use when the signal is weak but the ICP pain is well known. Still add a light signal if available.

## 3. BAB (Before → After → Bridge)

| Beat | Job |
| --- | --- |
| Before | Current painful state |
| After | Specific better state (metric + timeframe) |
| Bridge | How you get them there + soft CTA |

Use when you have a crisp quantified after-state.

## Voice

- **You/your** not we/our/I-centered product tours
- 3rd–5th grade reading level
- One idea per sentence

## Soft CTA (required)

Exactly one. Examples:

- `Is {{pain}} still on your plate, or already handled?`
- `Worth sending the 5-bullet checklist, or not useful?`
- `Open to a short teardown of {{thing}}?`

No calendar links on touch 1. No multi-asks.

## Poke-the-bear option

Replace or follow the CTA with one sharp question that makes ignoring costly:

- `If reply rates stay flat while send volume rises, where does the waste show up first for you?`

Still counts as the **single** ask — do not stack a second CTA.

## Spintax note

Spintax = **deliverability insurance** (variation across sends), **not** a reply-rate booster. Never spin the core offer into mush; keep meaning identical.
